# Word 代码块高亮与行号规则

## 目标

最终 Word 报告中的代码必须是可复制的原生文本，不是截图。代码块应当有准确语法高亮和左侧行号栏，视觉效果接近 IDE/Notebook 的代码阅读体验，同时保持课程实验报告的克制版式。

## 输入要求

- Markdown 代码块必须带语言标识，例如 opening fence 使用 `python`、`matlab`、`cpp`、`bash`。
- 如果输入代码块缺少语言标识，应根据文件扩展名或代码特征推断；无法推断时使用 `text`，但仍保留行号栏。
- 如果只摘录文件片段且知道源文件起始行，可在代码块前说明源文件和起始行；DOCX 阶段应从该行号开始编号。

## 推荐实现

- 优先使用 Pygments 做语言级 tokenization，例如 Python 的 `pygments.lexers.get_lexer_by_name` 和 `pygments.token.Token`。当前环境若缺少 Pygments，可安装 `pygments`；不要退回到只用黑色纯文本，除非确实无法安装依赖。
- 不要把 Pygments 生成的 HTML 截图粘进 Word。应将 token 转成 Word runs，逐段设置 `w:color`、`w:b`、`w:i` 等属性。
- 对 Python/OpenCV/NumPy 代码至少区分：关键字、字符串、注释、数字、函数/类名、内置名、普通标识符和操作符。

## Word 结构

每个代码块使用一个两列表格：

~~~text
┌────────┬──────────────────────────────┐
│ 行号栏 │ 代码文本                       │
└────────┴──────────────────────────────┘
~~~

- 一行源代码对应一行表格，不要把整段代码塞进一个普通段落。
- 左列为行号栏，宽度约 0.6-0.8 cm，右对齐，字体 Consolas 8-9pt，颜色 `9CA3AF`，底色 `EEF2F6`。
- 右列为代码栏，占剩余宽度，字体 Consolas 8.5-9pt，底色 `F8F8F8` 或与模板一致的浅灰。
- 表格整体使用窄边距，边框可为无边框或极浅灰边框 `D9E2EC`。不要用粗黑网格线。
- 段落不使用首行缩进，段前段后为 0，行距使用固定或最小值，参考 Lab1 样式可用约 `w:sz=18`、`line=210`。
- 代码栏文本必须保留空格和缩进。写入 OOXML 时，对含有前后空格的 `w:t` 添加 `xml:space="preserve"`；tab 统一转换为 4 个空格。

## 行号规则

- 默认从 1 开始编号。
- 如果代码片段标注了起始行，则从该起始行编号。
- 行号数量必须等于源代码实际行数，包括需要展示的空行。
- 长代码行允许在代码栏内自动换行，但不能因为视觉换行而新增行号；一个源代码行只对应一个行号。
- 不要手写固定行号。每次插入代码时从实际代码文本重新计算。

## 建议配色

可按 Pygments token 类型映射到 Word run 颜色：

| Token 类型 | 颜色 |
|---|---|
| Keyword | `0000FF` |
| Name.Builtin / Name.Function | `006699` |
| String | `008200` |
| Comment | `808080` |
| Number | `098658` |
| Operator / Punctuation | `000000` |
| Error | `B00020` |
| 普通文本 | `000000` |

如果参考报告提供了代码样式，优先复制参考报告的字体、字号、行距、底纹和颜色倾向；但仍要补上行号栏和真实语法高亮。

## QA

交付前检查：

- 代码块是可复制文本，不是图片。
- 每个代码块都有左侧行号栏。
- 行号连续且数量与源代码行数一致。
- 高亮颜色出现在 `word/document.xml` 的 run 级别，而不是整段单色文本。
- 缩进没有丢失，长行不超出版心、不被裁剪。
- 渲染页面中代码块不会遮挡后续文字，跨页时代码表格仍能读清。
