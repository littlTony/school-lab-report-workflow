# 实验过程及内容扩写模板

使用本模板前先判断原始 Markdown 是否已经足够详细。若原稿已经包含完整题干、必要原理、公式推导、变量解释、代码与说明，并且公式没有明显错误，则不要重新生成一份“详细版”；直接把原稿作为 Word 迁入来源。只有缺少内容时，才按本模板补写缺失部分。

公式保护规则：已有正确公式必须原样保留。补写推导时，在公式前后增加解释，不要为了“扩写”而重写公式本体、替换符号、合并公式或把 LaTeX 改成普通文字。

````markdown
# 实验过程及内容

## 一、概念题

### 1.1 原题题目完整保留

在题目下直接回答。概念题不写“题目分析”“实验原理”“实验设计”“核心代码”“代码说明”“本题小结”等小标题，也不为了格式统一而拆成多级模块。答案需要包含必要的定义、原理说明、公式推导、变量解释、结合题目的例子和结论，但组织形式应保持为直接解答。

需要公式时使用 LaTeX：

$$
y=f(x;\theta)
$$

其中，$x$ 表示输入，$y$ 表示输出，$\theta$ 表示模型或算法参数。若题目给出了具体参数或样例，应继续说明“在本题中，$x$ 对应 ...，$\theta$ 取 ...，因此 ...”。

### 1.2 原题题目完整保留

继续直接回答本题。

## 二、编程题

### 2.1 原题题目完整保留

**题目分析**

说明本题要解决的问题、输入输出、约束条件、与前后题目的关系，以及本题为什么需要使用相应算法。

**实验原理**

详细说明本题涉及的知识点、数学模型、算法原理、公式推导、变量含义和适用条件。涉及公式较多时，按下面顺序写：

1. 先定义题目中的输入、输出、坐标、信号、特征、模型参数或状态变量。
2. 从定义、几何关系、概率假设、物理规律、优化目标或模型结构出发推导核心公式。
3. 给出中间推导步骤，不只给最终公式。
4. 解释每个符号的含义、单位、维度或取值范围。
5. 结合本题举一个小例子，例如代入一个坐标点、卷积窗口、采样序列、输入张量形状、类别计数或题目参数。
6. 说明这个公式在代码中由哪个函数、循环、矩阵运算、模型层或指标计算实现。

**实验设计**

说明实验流程、数据读取、预处理、参数设置、核心步骤和输出保存方式。若需要列步骤，使用 `(1)`、`1)`、`a.` 等内部编号。

**核心代码**

代码文件：

```text
code/xxx.py
```

关键代码：

```python
# 放入真实代码或关键代码片段
```

**代码说明**

解释代码各部分如何对应实验原理和实验设计，说明关键参数、函数调用、输入输出路径和异常处理逻辑。
````

## 结果内容分离约束

本模板只用于生成 `实验过程及内容`。不要在本文件中新增以下小节：

- `实验结果`
- `结果展示`
- `结果分析`
- `数据处理分析`
- `实验结果分析`
- `本题结果和过程解释`
- `本题小结`

结果图片、CSV 表格、运行日志、指标统计、误差图和结果解释应交给 `school-lab-data-analysis`，由它生成 `数据处理分析` 部分。过程扩写文件最多保留结果图表路径作为内部交接信息，最终迁入 Word 的过程区时通常应移除该交接信息，且不要把交接信息变成最终报告里的 `结果文件` 清单。
